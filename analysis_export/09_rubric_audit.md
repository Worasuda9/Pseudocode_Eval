# Rubric Quality Audit

I have reviewed all 15 rubric files generated by the system across various problems (factorial, deduplication, recursion, progressive tax, etc.). Here is my assessment of whether the current rubrics are "good enough" and where they can be improved.

## ✅ What is working very well

1.  **Highly Specific:** The rubrics successfully tailor themselves to the exact problem. Instead of generic criteria like "Uses variables correctly," they say things like "Explicitly identifies the 5 vowels (a, e, i, o, u)."
2.  **Concrete and Measurable:** The criteria give the evaluator clear, objective things to look for. For example, in the nested functions problem, it explicitly checks if the inner function accesses variables `a` and `b` from the outer scope.
3.  **Good Edge Case Coverage:** Problems like the Leap Year calculator or Vowel Counter have excellent sub-criteria dedicated to boundary values and edge cases.

## 🔴 The Main Area for Improvement

There is a significant structural issue across almost all the rubrics: **Redundancy between Completeness and Correctness.** 

Because the generator prompt asks for problem-specific details in *all* dimensions, it tends to split the same requirement into two parts:
*   **Completeness:** Checks if a structural piece exists (e.g., "Includes conditional logic to check if a character is a vowel.")
*   **Correctness:** Checks if that piece is mathematically/logically right (e.g., "The conditional logic correctly identifies a, e, i, o, u.")

**Why this is a problem:**
When a student completely misses a step, they fail *both* the Completeness check and the Correctness check for that step. This leads to the double-penalization issue we saw during the evaluation traces.

### Examples of Redundancy Found:
*   **p010 (Word Character Count):** Completeness checks if steps exist to get the character count. Correctness checks if those steps get the accurate count.
*   **p012 (Vowel Counter):** Completeness requires a conditional statement for vowels. Correctness requires logic to identify vowels.
*   **p017 (Flatten 2D List):** Completeness checks for "mechanisms to iterate sub-lists." Correctness checks if it "correctly iterates sub-lists."

---

## 🛠️ Recommended Fix

To fix this, we need to adjust the `RUBRIC_SYSTEM_PROMPT` in `prompts.py` so the rubric generator understands the strict boundaries between dimensions. 

I recommend updating the generator instructions with the following constraints:
1.  **Completeness** should focus purely on the *inputs, outputs, data structures, and edge-case handling coverage* — not the presence of specific logical operators.
2.  **Correctness** should own all the *mathematical, algorithmic, and conditional logic* checks.

By drawing a hard line between "Did they handle the edge case?" (Completeness) and "Is the math right?" (Correctness), the generated rubrics will be much cleaner and prevent the LLM evaluator from getting confused.
